DenizenAdditions Events


Script events are used in 'world' script containers to run a script when something happens in the game.
These are only the ones DenizenAdditions adds, along with the parts of Denizen that the Denizen fork changes. For everything in Denizen itself, see the Denizen Meta Documentation.

Category: Discord


Namediscord thread archives|unarchives
Event Lines discord thread archives|unarchives
Triggerswhen a thread is archived or unarchived - by Discord itself after inactivity, by a user, or by a bot.
dDiscordBot's own 'discord thread archived' event does not actually fire on archiving: it is tied to the bot
losing access to a thread. This one listens to the archive flag itself.

Discord only sends this while the bot is connected: a thread archived during downtime is not reported later.
Switchesfor:<bot> to only process the event for a specified Discord bot.
group:<group_id> to only process the event for a specified Discord group.
parent:<channel_id> to only process the event for threads in a specified channel.
Contexts<context.bot> returns the relevant DiscordBotTag.
<context.group> returns the DiscordGroupTag.
<context.thread> returns the thread DiscordChannelTag.

RequiresdDiscordBot, DenizenAdditions

Namediscord user changes guild tag
Event Lines discord user changes guild tag
Triggerswhen the server tag (guild tag) a user shows next to their name changes: they put one on, take it off,
hide it, switch to another guild's tag, or the guild renames or turns off its tag.
A change of the badge alone does not count.

Only fires for users who share a group with the bot, once per connected bot that sees them.
Discord only sends this while the bot is connected: a change made during downtime is not reported later,
so compare against Tag:DiscordUserTag.has_guild_tag on startup if that matters.
Example
# Gives a role to whoever shows this group's tag, and takes it away when they stop.
on discord user changes guild tag group:123456789:
- define group <discord_group[mybot,123456789]>
- if <context.user.has_guild_tag[<[group]>]>:
    - discord id:mybot add_role user:<context.user> role:<[group].role[Tag wearer]> group:<[group]>
- else:
    - discord id:mybot remove_role user:<context.user> role:<[group].role[Tag wearer]> group:<[group]>
Switchesfor:<bot> to only process the event for a specified Discord bot.
group:<group_id> to only process the event when the old or the new tag belongs to a specified Discord group.
Contexts<context.bot> returns the relevant DiscordBotTag.
<context.user> returns the DiscordUserTag.
<context.old_tag> returns the tag text shown before, if any.
<context.new_tag> returns the tag text shown now, if any.
<context.old_group> returns the DiscordGroupTag the old tag belongs to, if any.
<context.new_group> returns the DiscordGroupTag the new tag belongs to, if any.

Name<entity> walks
Event Lines <entity> walks
Triggerswhen an entity moves in the slightest.
Does not fire for players - use Event:player walks for player movement.
Note that the 'in:<area>' switch is checked against the location the entity moved to, so it also fires when an entity moves into the area.
Contexts<context.entity> returns the EntityTag that moved.
<context.old_location> returns the LocationTag of where the entity was.
<context.new_location> returns the LocationTag of where the entity is.
<context.block_changed> returns an ElementTag(Boolean) of whether the entity moved to a different block.
<context.position_changed> returns an ElementTag(Boolean) of whether the entity's position changed (as opposed to only changing look direction).
<context.orientation_changed> returns an ElementTag(Boolean) of whether the entity's look direction (yaw/pitch) changed.
CancellableTrue - This adds <context.cancelled> and determine 'cancelled' or 'cancelled:false'
Has LocationTrue - This adds the switches 'in:<area>', 'location_flagged:<flag>', ...

Category: Player


Nameplayer (right|left) clicks <block>
Event Lines player (right|left) clicks <block>
Triggerswhen a player clicks on a block or in the air.
The "in:<area>" switch checks the clicked block, or the player's location when clicking in the air.
The "location_flagged:<flag>" switch only checks the clicked block, so it never matches clicks in the air.
Has PlayerAlways. - this adds switches 'flagged:<flag name>' + 'permission:<node>', in addition to the '<player>' link.
Switcheswith:<item> to only process the event if a specified item was held.
using:hand/off_hand/either_hand to only process the event if the specified hand was used to click.
type:<material> to only run if the block clicked matches the material input.
Contexts<context.item> returns the ItemTag the player is clicking with.
<context.location> returns the LocationTag of the clicked block, if any.
<context.relative> returns a LocationTag of the block in front of the clicked face, if a block was clicked.
<context.interaction_point> returns a LocationTag of the exact point that was clicked on the block. Only available when right clicking a block.
<context.hit_face> returns a LocationTag vector of the clicked block face (like '0,1,0' for the top of a block), if a block was clicked.
<context.click_type> returns an ElementTag of the Bukkit API click type 🔗https://jd.papermc.io/paper/org/bukkit/event/block/Action.html.
<context.hand> returns an ElementTag of the used hand, can be either HAND or OFF_HAND.
Determine"USE_BLOCK:<ElementTag(Boolean)>" to set whether the clicked block's own interaction (like opening a door or a chest) happens, regardless of the held item.
"USE_ITEM:<ElementTag(Boolean)>" to set whether the held item is used, regardless of the clicked block.
Cancelling or uncancelling the event afterwards (including from another script) overrides both.
CancellableTrue - This adds <context.cancelled> and determine 'cancelled' or 'cancelled:false'
Has LocationTrue - This adds the switches 'in:<area>', 'location_flagged:<flag>', ...
GroupPlayer
Warning(s)this event may in some cases double-fire, requiring usage of the 'ratelimit' command (like 'ratelimit <player> 1t') to prevent doubling actions.
this sometimes fires at unexpected times, eg when dropping an item.

Nameplayer server full check
Event Lines player server full check
Triggerswhen the server computes whether it is currently considered full for a connecting player, before the player has finished joining.
This runs very early in the connection process - the player has not actually joined yet, so most player data/state may not be available.
Should NOT be confused with Event:player joins.
Has PlayerWhen the player has previously joined (and thus the UUID is valid). - this adds switches 'flagged:<flag name>' + 'permission:<node>', in addition to the '<player>' link.
Switchesis_allowed:<true/false> to only handle the event when the player is (or isn't) currently allowed to join, before this event runs.
Contexts<context.name> returns the connecting player's name.
<context.uuid> returns the connecting player's UUID.
<context.is_allowed> returns whether the player is currently allowed to join (false means the server is currently considered full for them).
<context.kick_message> returns the currently planned kick message, that would be shown if the player ends up rejected.
Determine"ALLOWED" to let the player join even if the server would otherwise consider itself full.
"DENIED" to reject the player, keeping whatever kick message is already planned.
"KICK_MESSAGE:<ElementTag>" to reject the player and set a custom kick message.
